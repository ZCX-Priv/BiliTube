## BiliTube 性能优化计划

### 一、后端优化 (backend.py) - 重点（资源占用可控）

#### 1. 有限内存缓存

* LRU 缓存，限制最多 200 条记录

* 单个响应最大 512KB

* 60 秒自动过期

* 防止内存无限增长

#### 2. 轻量级 HTTP 压缩

* 仅压缩 JSON 响应 (>1KB)

* 使用 gzip（低 CPU 开销）

* 压缩级别 1（最快，最低 CPU 占用）

#### 3. 连接池优化

* urllib3 PoolManager（最大 100 连接）

* 连接超时 10 秒

* 自动清理空闲连接

#### 4. 请求去重

* 使用 set 记录正在进行的请求

* 500ms 内相同请求只发起一次

* 减少重复请求对 API 的压力

### 二、前端优化 (兼容 Chrome 80+)

#### 1. 占位图

* `img/thumbnail-placeholder.png` - 视频封面占位图 (16:9)

* `img/avatar-placeholder.png` - 头像占位图 (圆形 1:1)

#### 2. 图片加载优化

* 封面/头像使用 `onerror` 回退到占位图

* 使用 `loading="lazy"` 延迟加载

* 使用 CSS 动画实现渐进式加载效果

#### 3. API 请求并行化

* 视频详情页使用 `Promise.all()` 并行获取

* 视频信息、播放地址、弹幕、评论、相关推荐同时请求

#### 4. 数据缓存层

* 实现 LRU 内存缓存（最多 50 条）

* 页面切换时复用缓存数据

#### 5. DOM 优化

* 使用 `DocumentFragment` 批量插入

* 图片使用 CSS `will-change` 优化渲染

### 三、资源控制策略

| 资源   | 限制值     |
| ---- | ------- |
| 缓存条数 | ≤200 条  |
| 单条缓存 | ≤512KB  |
| 连接池  | ≤100 连接 |
| 压缩级别 | 1（最快）   |
| 前端缓存 | ≤50 条   |
